# TrailPack documentation archive

This archive preserves dated decisions, research, validation, and design evidence.
It is not the primary source for current product behavior. Start with the
[documentation index](../README.md), then use these records when investigating
why a decision was made or what passed at a particular release checkpoint.

| Area | Contents |
|---|---|
| [Project records](project/README.md) | Historical requirements, schedules, implementation plans, and the detailed Priority 1 roadmap |
| [Research](research/README.md) | Early provider and trail-data feasibility studies |
| [Validation](validation/README.md) | Dated release, security, reliability, performance, and acceptance evidence |
| [Interface history](ui/README.md) | Earlier workflow notes, wireframes, concepts, and rendered screenshots |
| [Release detail](releases/README.md) | Full pre-cleanup changelog narrative |

Historical statements such as “pending,” “local,” or “planned” describe the
state at the date of the record. Check the current [README](../../README.md),
[changelog](../../CHANGELOG.md), and [roadmap](../roadmap.md) for present status.

The [September 9 cleanup audit](2026-09-09-documentation-cleanup-audit.md)
records the before/after inventory, decisions, assumptions, and reversal path.
